# TimeTrace

Трекер времени для Linux и Windows. Linux-версия поддерживает **окружения и оконные менеджеры на X11** и **Wayland-композиторы с доступным API фокуса и простоя** (GNOME, KDE, Cinnamon, Sway, Hyprland, MangoWM, niri, COSMIC и другие). Windows-версия поставляется как один `TimeTrace.exe` x64 для Windows 10/11; подробности — в [инструкции для Windows](docs/windows.md). Показывает, в каких приложениях и окнах вы провели день, отслеживает простой (idle) и переходы в спящий режим, живёт в системном трее.

## Возможности

- **Названия и иконки приложений** — по установленным `.desktop`-ярлыкам, включая XDG-каталоги, Flatpak и Snap. Поддерживаются идентификаторы Wayland/GNOME, `StartupWMClass`, имена исполняемых файлов, абсолютные пути к иконкам и системные темы. Если собственная иконка отсутствует или недоступна, показывается встроенная запасная.
- **Таймлайн дня** — две дорожки: активность по приложениям и простой/активность, с переходом по дням.
- **Не у компьютера** — после заданного порога без ввода мыши и клавиатуры верхняя дорожка становится красной; при наведении показаны статус «Не у компьютера» и время. Полноэкранное активное приложение (в том числе видео YouTube) продолжает считаться активностью без ввода. Живые обои, уведомления и обновление изображения не сбрасывают простой. В Wayland с протоколом idle-notify v2 используются события только пользовательского ввода; на старых композиторах v1 остаётся системное определение простоя с учётом блокировщиков сна.
- **Обнаружение сна** — засыпание/пробуждение системы отмечаются на таймлайне отдельно от простоя.
- **Системный трей** — окно сворачивается в трей вместо закрытия; иконка трея пропускается, если у окружения нет `StatusNotifierWatcher` (например, GNOME без соответствующего расширения).
- **Автозагрузка** — запуск при входе в систему сразу в трей, без открытия окна на рабочем столе.
- **Тема** — светлая, тёмная или системная, со слежением за сменой темы GTK/Qt на лету.
- **Один экземпляр приложения** — повторный запуск через D-Bus поднимает и активирует уже открытое окно вместо второго процесса.

## Поддерживаемые окружения

| Сессия / композитор | Источник активного окна | Источник простоя |
|---|---|---|
| X11, включая старые WM | EWMH, резервно ICCCM input focus | XScreenSaver |
| GNOME 51 | Расширение TimeTrace | GNOME bridge |
| KDE / KWin, включая LXQt с KWin | KWin script | ext-idle-notify / KDE idle fallback |
| UKUI / ukui-kwin | Профиль D-Bus UKUI / KWin script | ext-idle или KDE idle |
| Cinnamon / Muffin | Встроенный D-Bus API, без расширения | Muffin IdleMonitor |
| Sway/SwayFX, labwc, Wayfire, Hyprland, MangoWM, Phosh, Qtile, river-classic | wlr foreign toplevel management | ext-idle-notify |
| niri | wlr, резервно IPC | ext-idle-notify |
| COSMIC | ext-list + COSMIC toplevel info v2 | ext-idle-notify |
| Свежий Treeland, новый River | wlr, с ограничениями версии | ext-idle-notify |
| Budgie, LXQt, MATE, Xfce и другие оболочки | API фактического композитора | API фактического композитора |

Бэкенд выбирается автоматически при запуске. Название DE не ограничивает общий
Wayland-бэкенд: программа проверяет доступные протоколы. Hyprland и niri имеют
также прямой IPC fallback без запуска внешних команд.

**Универсального API фокуса во всех Wayland-окружениях нет.** Для vanilla dwl,
Weston, Enlightenment Wayland, Lomiri и ряда конфигураций нет подтверждённого
полного маршрута. Отсутствующие API отображаются в строке состояния приложения.
Ограничения версий, отдельные функции и список популярных и редких окружений
со ссылками на исходники — в [полной матрице совместимости](docs/compatibility.md).

## Установка

В GNOME 51 на Wayland TimeTrace сам устанавливает и включает расширение при
запуске. Если потребуется повторный вход в сеанс, подсказка появится в окне
приложения; подробнее — в [инструкции](docs/gnome.md). Имя приложения,
команда `timetrace`, настройки и каталог истории сохраняются.

Готовые пакеты — на странице [Releases](https://github.com/post-code-FF/timetrace/releases):

- Debian / Ubuntu / Mint: `sudo apt install ./timetrace_0.1.8_amd64.deb`;
- Fedora / совместимые RPM-дистрибутивы: `sudo dnf install ./timetrace-0.1.8-1.x86_64.rpm`
  (в openSUSE — `zypper install ./имя-пакета.rpm`);
- Arch / CachyOS / EndeavourOS: `sudo pacman -U ./timetrace-git-0.1.8-1-x86_64.pkg.tar.zst`.

Начиная с 0.1.8, обновление любого из трёх пакетов автоматически перезапускает уже работающие экземпляры TimeTrace от имени их пользователей. История и настройки сохраняются; закрытое приложение при обновлении не запускается. Это работает и при переходе с пакетной версии 0.1.7. Независимые локальные копии вне `/usr/lib/timetrace` установщик не изменяет.

Всего **три установочных пакета**, без пользовательских вариантов сборки.
Каждый автоматически выбирает совместимые компоненты для glibc вашей системы;
смена окружения или обновление дистрибутива не требуют выбора другого пакета.
Требуется Linux x86_64 с glibc ≥2.31. Имя Arch-пакета `timetrace-git` сохранено
для обновления существующих установок и отличия от другой программы `timetrace` в AUR.

### Из исходников

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
timetrace
```

Требуется Python ≥ 3.11.

## Разработка

```bash
# тесты
pip install -e ".[dev]"
pytest

# ручной запуск
python -m timetrace
```

Структура проекта:

- `src/timetrace/backends/` — бэкенды простоя/активного окна/сна для X11, GNOME, KWin, Cinnamon, wlr/COSMIC и IPC-композиторов;
- `src/timetrace/tracking/` — координатор, склеивающий события бэкендов в записи БД;
- `src/timetrace/ui/` — главное окно, таймлайн, список приложений, трей, диалог настроек;
- `src/timetrace/assets/` — GNOME Shell extension и KWin script, устанавливаемые бэкендами активного окна;
- `packaging/` — PyInstaller-спека, сборка `.deb`/`.rpm` через `fpm`, Arch `PKGBUILD`, сборка бинарника в Docker (для совместимости по glibc).

## Сборка пакетов

```bash
bash packaging/build_in_docker.sh
docker build -f packaging/docker/Dockerfile.fpm -t timetrace-fpm .
docker run --rm -v "$PWD:/source" -w /source timetrace-fpm bash packaging/build_deb_rpm.sh
bash packaging/build_arch.sh
bash packaging/test_packages.sh
```

Готовые `.deb`, `.rpm` и `.pkg.tar.zst` появляются в `packaging/out/`.
Внутренние runtime собираются на Ubuntu 20.04/22.04/24.04; launcher запускает
новейший совместимый с установленной glibc. Fontconfig и FreeType остаются
системными, необходимые системные библиотеки объявлены зависимостями.
Подробности — в [документации сборки](packaging/docker/README.md).

GitHub Actions (`Linux release builds`) собирает runtime и три пакета при push
в `release/**` или ручном запуске, проверяет тесты, D-Bus, shell integration,
headless Wayland и установку в контейнерах. Артефакт содержит три установщика
и `SHA256SUMS`. Слияние в main само по себе не публикует релиз.
