# Windows-порт TimeTrace — дизайн

## Цель и границы

Добавить в существующий Python/PySide6-проект нативный Windows-вариант TimeTrace, сохранив Linux-версию, её поведение и визуальный интерфейс. Итоговый пользовательский артефакт — один `TimeTrace.exe` x64 без установленного Python и без Docker.

Подтверждённая граница совместимости: **Windows 8.1, 10 и 11 x64**. Windows 7 и Windows 8.0 исключены по решению пользователя. Это важная техническая граница: текущие Python/Qt не гарантируют работу на этих старых системах; обещать единый современный exe для них нельзя.

## Что найдено в исходниках

- Версия проекта: `0.1.8`; базовая ревизия: `7da230c`.
- UI уже написан на PySide6 и отделён от Linux-бэкендов: главное окно, две дорожки таймлайна, список приложений, настройки, трей.
- Учёт и SQLite-схема находятся в `tracking/coordinator.py` и `db.py`; их не нужно переписывать.
- Linux-специфичны выбор активного окна, idle, сон через logind, D-Bus single-instance, XDG-пути, `.desktop`/иконки, автозагрузка и обслуживание пакетов.
- `pywayland` не собирается на Windows: это ожидаемо, поскольку Wayland-бэкенды не используются в Windows-сборке.
- Исходный прогон на Windows: 237 тестов прошли, 22 упали, 1 пропущен; отдельный модуль обслуживания пакетов не импортируется из-за `pwd`. Падения относятся к Linux-only сценариям и путям/разделителям, а не к общей SQLite/UI-логике.

## Подходы

1. **Выбран: платформенные адаптеры внутри текущего приложения.** Общие UI, конфигурация, SQLite и координатор остаются общими; Windows получает свои реализации системных интеграций. Это сохраняет функциональность и позволяет выпускать один exe.
2. Отдельное Windows-приложение с копией UI отвергнуто: оно быстро разойдётся с Linux-версией по внешнему виду и исправлениям.
3. Wine/прослойка Linux API отвергнута: она не даёт нативного трея, автозагрузки, Win32-фокуса и корректной работы сна/idle.

## Архитектура

### Общие части без изменения поведения

Сохранить `MainWindow`, виджеты таймлайна, палитры, формат длительностей, настройки, `Store`, `TrackingCoordinator` и формат TOML/SQLite. Платформенные решения должны быть точками выбора реализации, а не ветвлением внутри отрисовки.

### Windows-интеграции

- Активное окно: Win32 `GetForegroundWindow`, `GetWindowTextW`, `GetWindowThreadProcessId`; имя процесса и путь — через Win32 API. Класс ресурса должен быть стабильным идентификатором приложения, а заголовок сохраняется отдельно, как в Linux.
- Idle: `GetLastInputInfo`, с тем же порогом и событиями idle/resume. Полноэкранное окно должно освобождаться от idle так же, как в Linux; для этого используется геометрия окна и монитор.
- Сон/пробуждение: скрытое окно сообщений Qt/Win32 с `WM_POWERBROADCAST`, события `PBT_APMSUSPEND` и `PBT_APMRESUME*`.
- Пути: `%APPDATA%\TimeTrace\config.toml` и `%LOCALAPPDATA%\TimeTrace\data.db`; при отсутствии переменных — безопасный пользовательский fallback. Linux продолжает использовать XDG.
- Автозагрузка: текущий пользователь, ключ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, команда с абсолютным путём к exe и `--minimized`; снятие галочки удаляет значение.
- Single-instance: именованный mutex плюс локальное сообщение/IPC для поднятия существующего окна; без второго процесса и без D-Bus.
- Тема: светлая/тёмная палитры остаются теми же; системный режим читает настройку Windows и отслеживает её изменение.
- Иконки и имена: извлечение иконки исполняемого файла и имени файла/метаданных; Steam-названия сохраняются через Windows-библиотеки Steam. Встроенная запасная иконка остаётся общей.
- Трей: существующий `QSystemTrayIcon` и меню без изменения текстов.

### Сборка и зависимости

Linux-зависимости объявляются с platform markers; Windows не устанавливает `pywayland` и X11-зависимости. Для Windows добавить только необходимые bindings к Win32. PyInstaller собирает `onefile`, `console=False`, x64, с общими assets и Windows entry point. Linux spec и packaging не изменяются.

## Проверка

- Сначала тесты на платформенные адаптеры с подменяемыми Win32-функциями: фокус, смена процесса/заголовка, idle, fullscreen, sleep/wake, пути, реестр автозагрузки, single-instance и тема.
- Затем общие тесты UI/БД/координатора и Windows-набор; Linux-only тесты маркируются и не запускаются как Windows-функциональность.
- Локальный запуск исходного Python-приложения и собранного exe: окно, настройки, трей, сохранение истории, переход дня, повторный запуск, автозагрузка.
- Проверка PE-заголовка x64 и зависимостей exe. Реальная проверка на Windows 8.1 невозможна на текущем ПК без отдельной VM/устройства; это будет явно указано, а не выдано за выполненную проверку.
- Docker не используется.

## Публикация

Работа ведётся в ветке `windows-port`. После локальной проверки и ревью изменения объединяются в `main`, затем публикуется новый релиз с одним Windows exe и SHA256. Публикация релиза выполняется только после успешной сборки и проверок; существующие Linux-релизные артефакты не заменяются.

## Не входит

- Переписывание backend-логики учёта или схемы БД.
- Изменение внешнего вида Linux-версии.
- Поддержка Windows 7/8.0, x86, ARM64.
- Установка системных драйверов, службы Windows или обязательного установщика.
- Гарантия совместимости с Windows 8.1 без фактического теста на этой ОС.
