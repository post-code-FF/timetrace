# TimeTrace GNOME 51 — локальный тестовый форк

Статус: 202 автоматических теста пройдены; в реальной GNOME 51-сессии
подтверждены переключения приложений, простой, блокировка и восстановление.
Собран отдельный Arch-пакет с синей иконкой. Suspend/resume, игры и несколько
мониторов требуют дальнейшей живой проверки.

Основа: https://github.com/post-code-FF/timetrace, commit
c9c7bf2 (0.1.4), ветка `fix/gnome-51-reliable-tracking`.
Исходный стек сохранён: Python >=3.11, PySide6/Qt, SQLite, python-xlib,
pywayland. README оригинала и Arch-пакет объявляют MIT; отдельного LICENSE
в полученном дереве upstream нет. Публикация форка не выполнялась.

## Подтверждённая диагностика

* Arch Linux; GNOME Shell 51.1 (`gnome-shell 1:51.1-1`); XDG_SESSION_TYPE=wayland,
  XDG_CURRENT_DESKTOP=GNOME. Проверено в текущей сессии, а не предположено.
* `/usr/bin/timetrace`, пакет `timetrace-git 0.1.4-1`, упакованный бинарник,
  источник пакета указывает на репозиторий выше. Это не Python-пакет системы.
* Оригинальный UUID `timetrace@timetrace.app`: Enabled Yes, State OUT OF DATE;
  metadata поддерживает только Shell 45–50. `/org/timetrace/ActiveWindow`
  не экспортирует интерфейс. Поэтому приложение не получает фокус окон.
* В journalctl --user и в предоставленном пользователем выводе:
  `AddIdleWatch: unexpected gdbus reply '(uint32 5,)'`.
  Парсер исходников принимает `(5,)`, но отвергает корректный типизированный
  GVariant. Это отдельная подтверждённая ошибка, останавливающая idle.
* Вывод текущего процесса направлен в `/dev/pts/0`. История этого терминала
  не читалась; прочитаны journalctl и переданный пользователем лог.
  Сообщения Qt portal/textinput зарегистрированы, но их связь с фокусом
  не доказана.

## Архитектура

Новое расширение `timetrace-fork@local` использует Shell.WindowTracker и
Meta.Display.focus_window. Приоритет идентификатора — desktop ID из Shell;
WM_CLASS — помеченный запасной источник. PID не нужен. Фокус глобален для
всех мониторов и рабочих столов; несколько окон одного приложения дают один
последовательный foreground-интервал. Диалоги разрешаются WindowTracker.
Fullscreen не требует отдельного перехвата.

Расширение получает lock из Main.sessionMode, idle из
`global.backend.get_core_idle_monitor().get_idletime()`. Эти методы проверены
в установленном Meta-51.gir; реальные вызовы также подтверждены в живой сессии.
На lock title и app ID не передаются. Сессии user/unlock-dialog объявлены
явно, а disable отправляет недоступность и освобождает сигналы/таймер/объект.

Протокол org.timetrace.GnomeFork.Bridge1, объект
/org/timetrace/GnomeFork/Bridge на имени org.gnome.Shell: read-only GetEvents
и Changed. Нет Shell.Eval, отключения проверки версий, записи ввода или обхода
Wayland. Qt использует постоянную шину и асинхронные вызовы с timeout 1500 мс,
проверяет протокол и epoch/sequence, повторяет запрос раз в секунду.
В Shell хранится ограниченный буфер 600 событий для повторного чтения.
Новый клиент начинает с текущего состояния; пропущенные уведомления в рамках
буфера восстанавливаются. Перезапуск Shell, переполнение и недоступность
останавливают foreground с последней подтверждённой точки; неизвестные
промежутки не приписываются последнему приложению.

Координатор раздельно хранит idle/blocked/sleep: событие активности не может
прервать suspend или lock. logind PrepareForSleep оставлен из оригинала.
Переходы БД атомарны, повторные события не открывают перекрывающиеся интервалы,
пустой фокус закрывает foreground. Очередь сбрасывается перед выходом; heartbeat
раз в секунду ограничивает продолжение незакрытого интервала после аварии.

Сохранены UI, статистика по дням, таймлайн, настройки, темы, имена/иконки,
трей и KDE/X11 backend. Отдельных категорий и экспорта отчётов в upstream нет.
Background running time не добавлен: наличие процесса/окна не означает
foreground; текущие таблицы и UI показывают именно активное приложение.

## Запуск

Все команды выполняются из каталога этого форка. Уже создана локальная .venv.
Установка зависимостей для новой копии:

```bash
python -m venv .venv
.venv/bin/pip install -e '.[dev]' build
```

Отдельное расширение устанавливается только явным запуском:

```bash
./scripts/install-extension.sh
```

Скрипт пишет только новый UUID в пользовательский каталог расширений и
отказывается перезаписывать существующий каталог. Если GNOME не обнаружил
новый UUID, сохраните работу, выйдите из сессии и войдите снова. Затем:

```bash
gnome-extensions enable timetrace-fork@local
gnome-extensions info timetrace-fork@local
```

Требуется State ACTIVE. Не отключайте проверку версий расширений.

Необязательный перенос истории (сначала до первого запуска форка):

```bash
.venv/bin/python scripts/copy-original-data.py
```

Скрипт открывает оригинальную SQLite только read-only и использует backup API,
согласованный при работающем приложении. Целевая база не перезаписывается.
Незакрытые интервалы копии закрываются временем копирования. Настройки копируются
с отключённой автозагрузкой форка. Оригинальные файлы не изменяются.

```bash
TIMETRACE_DEBUG=1 ./scripts/run-fork.sh
```

Пути по умолчанию: ~/.local/share/timetrace-gnome-fork/data.db,
~/.config/timetrace-gnome-fork/config.toml. Имя D-Bus приложения
org.timetrace.GnomeFork.App; оригинал может работать параллельно. Подробный лог
в stderr включается TIMETRACE_DEBUG=1; без него выводятся предупреждения.
Заголовки окон в диагностический лог не включаются (в БД сохраняются как раньше).
Автозагрузка не включается автоматически; отдельного systemd unit не требуется.

Wheel находится в dist/. Устанавливайте его только в отдельный venv, поскольку
Python namespace timetrace общий с исходным проектом. При wheel-установке
скопируйте также scripts/ либо используйте исходное дерево.

## Проверки

```bash
.venv/bin/pytest -q
TIMETRACE_PRIVATE_BUS_TEST=1 dbus-run-session -- .venv/bin/python scripts/test-dbus-integration.py
```

На этапе подготовки: 202 теста пройдены, 5 upstream DeprecationWarning Qt.
GJS harness проверяет синтаксис модуля и протокол с подставными API Shell:
фокус, отсутствие фокуса, lock/privacy, idle, replay, overflow, disable.
Это не запуск расширения в Shell. Отдельно успешно проверен реальный
транспорт D-Bus → Qt async → backend → coordinator → SQLite на изолированной
шине с тестовым сервером, включая сравнение точных интервалов.
Копия прежней истории открылась в UI; оригинальная база не изменялась.
Живой тест длительностью 119.6 с записал 79.893 с foreground, без пересечений
интервалов; при lock учёт остановился и восстановился после unlock.
Независимого хронометража действий пользователя не было.

Живая проверка после State ACTIVE (отдельная БД, idle 10 секунд):

```bash
.venv/bin/python scripts/probe-gnome.py --seconds 120 --idle-seconds 10 --output /tmp/timetrace-live-test
```

Каталог не должен содержать старую probe.db. Во время записи переключайтесь
между терминалом, браузером, файловым менеджером, редактором; держите каждое
окно активным примерно 10 секунд и двигайте мышь, чтобы не включался idle.
Затем не трогайте ввод 15 секунд, вернитесь, заблокируйте экран на 10 секунд
и разблокируйте. report.json содержит интервалы, сумму foreground, CPU и RAM.
Для игры/fullscreen, двух окон одного приложения, нескольких мониторов,
рабочих столов и suspend/resume повторите запись дольше (--seconds 300).
Для каждого сценария сравнивайте timestamp переходов с фактическими действиями.
Сон выполняйте вручную, сохранив работу; скрипт сам систему не усыпляет.

## Ограничения до приёмки

* Живые фокус, lock и idle проверены; suspend, игры и несколько мониторов пока не проверены.
* Поддержка нового расширения объявлена только для установленного GNOME 51.
  KDE/X11 код сохранён, но реальная проверка этих сессий не выполнена.
* Idle опрашивается раз в секунду; точность порога до примерно 1 секунды плюс
  задержки планировщика. Фокус — по сигналу Shell; события одной миллисекунды
  не дают различимого ненулевого интервала.
* При аварии теряется максимум последний период heartbeat при нормально
  работающем event loop; при зависании время до последнего checkpoint остаётся
  консервативной границей. При потере буфера неизвестное время не восстанавливается.
* Wall-clock хранится как в upstream. Обратный перевод часов ограничивается
  последним timestamp, чтобы не создавать отрицательные интервалы; точность
  при ручной смене часов не гарантируется.
* Lock и недоступный backend отображаются существующим состоянием idle;
  отдельной дорожки locked/unknown в прежней схеме нет.
* После новой пользовательской сессии требуется запуск в её окружении; восстановление имени Shell и переподключение Qt реализованы; смена адреса шины требует
  нового окружения запуска. Сам перезапуск шины ещё не проверен.
* В живом тесте backend-процесс: 0.311 с CPU за 119.6 с, peak RSS 45216 KiB.
  Это измерение тестового процесса, а не отдельное измерение накладных расходов Shell.

## Откат

Закройте форк; оригинальный `/usr/bin/timetrace` и его база остаются на месте.
Отключить новое расширение:

```bash
gnome-extensions disable timetrace-fork@local
```

Удалять оригинальную БД, оригинальный UUID и пакет timetrace-git не нужно.
История тестовой версии не сливается обратно автоматически. При включении
автозагрузки форка отключите её в его настройках перед откатом.

Полный список изменённых файлов находится в CHANGED-FILES.txt.
