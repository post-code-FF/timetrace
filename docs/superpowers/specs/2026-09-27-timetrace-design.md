# TimeTrace — дизайн

Дата: 2026-09-27
Статус: черновик на ревью пользователя

## 1. Назначение

Нативное Linux-приложение для персонального учёта времени за компьютером —
упрощённый аналог ManicTime. Показывает по дням: когда компьютер
использовался, когда был простой ("не у компьютера"), и сколько времени
какое приложение было в фокусе. Данные хранятся локально и бессрочно, пока
приложение установлено.

Целевая среда: любой Linux с X11 или Wayland-сессией, независимо от
окружения рабочего стола (KDE, GNOME, Cinnamon, XFCE, MATE и др.).
Приложение не привязывается к одному DE — трекинг простоя и активного
приложения реализован через набор бэкендов (раздел 3), между которыми
происходит автоматический выбор по типу сессии/DE при старте. Разработка и
проверка ведётся на машине автора: KDE Plasma 6.7.5, Wayland.

## 2. Стек

- **Язык/UI**: Python 3 + PySide6 (Qt6, LGPL).
- **Хранение**: SQLite (`sqlite3` из стандартной библиотеки).
- **Отслеживание простоя и активного окна**: набор независимых бэкендов на
  X11 (`python-xlib`), D-Bus (GNOME/Cinnamon Idle Monitor, KWin Scripting) и
  Wayland-протоколе `ext-idle-notify-v1` (`pywayland`) — см. раздел 3.
- **Упаковка**: PyInstaller (единый бинарник) → `.deb` и `.rpm` через `fpm`;
  для Arch — отдельный бинарный `PKGBUILD`.

Имя проекта/бинарника: **TimeTrace** (slug `timetrace`).
- Бинарник: `timetrace`
- Конфиг: `~/.config/timetrace/config.toml`
- Данные: `~/.local/share/timetrace/data.db`
- D-Bus сервис приложения: `org.timetrace.App`
- Автозапуск: `~/.config/autostart/timetrace.desktop`

## 3. Архитектура процесса

Один процесс. Внутри:

- **UI (главный поток Qt)** — главное окно + трей-иконка.
- **IdleBackend** и **ActiveWindowBackend** — два независимых интерфейса
  (Python `Protocol`), у каждого несколько реализаций под конкретное
  окружение. При старте приложение определяет сессию (`XDG_SESSION_TYPE`,
  `XDG_CURRENT_DESKTOP`, наличие Wayland/X11 дисплея) и выбирает первую
  подходящую реализацию каждого интерфейса. Оба интерфейса работают
  событийно (колбэк/сигнал при смене состояния), без поллинга.
- **Writer** — по приходу событий от бэкендов (idle/resume, смена активного
  окна) закрывает текущий открытый интервал в SQLite и открывает новый.

Закрытие окна сворачивает в трей и не останавливает трекинг. Полный выход —
только через пункт "Выход" в меню трея (останавливает бэкенды, закрывает
БД).

### IdleBackend — реализации и порядок выбора

1. **X11ScreenSaverIdleBackend** (сессия X11, `python-xlib`, расширение
   `XScreenSaver`, `XScreenSaverQueryInfo`) — работает под любым DE в X11
   (XFCE, Cinnamon, MATE, X11-сессии KDE/GNOME и т.д.). Опрашивает idle-время
   таймером раз в несколько секунд (расширение не даёт push-уведомлений) и
   сравнивает с порогом.
2. **MutterIdleMonitorBackend** (сессия Wayland, на шине присутствует
   `org.gnome.Mutter.IdleMonitor` или `org.cinnamon.Muffin.IdleMonitor`) —
   GNOME и Cinnamon на Wayland. Событийно: `AddIdleWatch(threshold_ms)` +
   сигнал `WatchFired`, `RemoveIdleWatch`/пересоздание при смене порога.
3. **WaylandExtIdleNotifyBackend** (сессия Wayland, протокол
   `ext_idle_notifier_v1` через `pywayland`) — KWin (KDE), Hyprland, Sway и
   другие компоситоры, реализующие этот протокол. Событийно: `idled`/
   `resumed`.
4. Если ни один бэкенд не применим — простой не отслеживается, "Использование
   компьютера" рисуется только зелёным всё время работы приложения;
   в настройках рядом с порогом простоя появляется пометка "не
   поддерживается в этом окружении".

Порядок 1→2→3 определяется типом сессии, а не перебором — для X11 сразу
берётся `X11ScreenSaverIdleBackend`; для Wayland сначала пробуется D-Bus
(дешевле и не требует протокольных биндингов), затем `ext-idle-notify-v1`.

### ActiveWindowBackend — реализации и порядок выбора

1. **X11EwmhActiveWindowBackend** (сессия X11, `python-xlib`) — слушает
   `PropertyNotify` на корневом окне по `_NET_ACTIVE_WINDOW`, по новому
   активному окну читает `WM_CLASS`/`_NET_WM_PID`. Универсально для любого
   X11 WM/DE (это и есть основное покрытие "прочих окружений" — XFCE,
   Cinnamon, MATE сегодня по умолчанию работают на X11).
2. **KWinScriptActiveWindowBackend** (Wayland + `XDG_CURRENT_DESKTOP`
   содержит `KDE`) — уже описанный KWin-скрипт, загружаемый через
   `org.kde.kwin.Scripting.loadScript`, сообщающий смену окна в D-Bus сервис
   `org.timetrace.App` приложения.
3. **GnomeShellExtensionBackend** (Wayland + `XDG_CURRENT_DESKTOP` содержит
   `GNOME`) — маленькое расширение GNOME Shell (JS), которое приложение
   при первом запуске копирует в
   `~/.local/share/gnome-shell/extensions/timetrace@timetrace.app/` и
   включает через `gnome-extensions enable` / D-Bus
   `org.gnome.Shell.Extensions`. Расширение экспонирует D-Bus-метод,
   возвращающий класс/PID активного окна, и шлёт сигнал при смене фокуса.
   **Известное ограничение GNOME**: свежеустановленное расширение на Wayland
   иногда подхватывается только после перелогина сессии — при первом
   запуске в этом окружении в UI показывается ненавязчивое уведомление
   "перелогиньтесь, чтобы трекинг приложений заработал", если расширение не
   включилось сразу.
4. Если ни один бэкенд не применим (прочие Wayland-компоситоры вне KDE/GNOME
   — экспериментальные Wayland-сессии Cinnamon/XFCE и т.п.) — дорожка
   "Приложения" и список приложений внизу остаются пустыми, но дорожка
   "Использование компьютера" продолжает работать через IdleBackend.

### Риски и порядок проверки в реализации

Первая задача реализации (до остального UI) — прототипы обоих интерфейсов
для окружения разработки (KDE/Wayland): `WaylandExtIdleNotifyBackend`
(проверить, что `pywayland` подтягивает staging-протокол
`ext-idle-notify-v1`) и `KWinScriptActiveWindowBackend`. Если `pywayland` не
подтягивает staging-протоколы автоматически — запасной вариант: маленький
скомпилированный (Rust) хелпер-бинарник, реализующий тот же протокол и
печатающий события в stdout, который Python-процесс запускает как
подпроцесс. `X11ScreenSaverIdleBackend`/`X11EwmhActiveWindowBackend` и
`MutterIdleMonitorBackend`/`GnomeShellExtensionBackend` проверяются позже
по тем же интерфейсам, без изменений в остальной архитектуре — это и есть
смысл разделения на бэкенды.

## 4. Модель состояний и данных

Две независимые дорожки данных за день, обе — последовательности
непересекающихся интервалов `[start, end)`:

1. **Использование компьютера**: состояния `active` (зелёный) и `idle`
   (красный). Отсутствие интервала в диапазоне времени = компьютер выключен
   / приложение не запущено (пусто на шкале). Переход в `idle` происходит
   в момент прихода события `idled` от компоситора (без ретроактивного
   пересчёта момента начала простоя — просто и предсказуемо).
2. **Приложения**: интервалы `(resourceClass, start, end)` — активное окно
   в фокусе. Копится **только** пока состояние "Использование компьютера"
   = `active`. Во время `idle` и при отсутствии данных дорожка "Приложения"
   тоже пустая — так суммарное время по приложениям совпадает с "Всего".

SQLite-схема (упрощённо):

```sql
CREATE TABLE presence_intervals (
  id INTEGER PRIMARY KEY,
  state TEXT NOT NULL CHECK(state IN ('active','idle')),
  start_ts INTEGER NOT NULL,  -- unix ms
  end_ts INTEGER              -- NULL = открытый интервал (ещё идёт)
);

CREATE TABLE app_intervals (
  id INTEGER PRIMARY KEY,
  resource_class TEXT NOT NULL,
  window_title TEXT,
  start_ts INTEGER NOT NULL,
  end_ts INTEGER
);
```

При старте приложения, если в БД остался открытый интервал (`end_ts IS
NULL`) от предыдущего запуска (например, процесс был убит) — он закрывается
временем последней имеющейся записи/события, чтобы не тянуть "зависший"
интервал на текущий день.

Иконка приложения не хранится в БД — резолвится на лету по
`resource_class` через поиск `.desktop`-файла (совпадение по
`StartupWMClass`/имени Exec) и `QIcon.fromTheme`, с кэшем в памяти на время
работы процесса.

## 5. Интерфейс

Одно главное окно, без вкладок "Документы и интернет", "Метки",
"Расписание", "Статистика".

**Верх** — панель даты: `<` кнопка, отображение даты, `Сегодня`, `>`
кнопка (кнопка `>` неактивна, если текущая дата уже сегодня). Пролистывание
без ограничения по глубине — вся история с момента первой записи в БД.

**Середина** — две дорожки шкалы на 24 часа (00:00–24:00) с часовыми
метками:
- "Использование компьютера" — сегменты зелёный (active) / красный (idle) /
  пусто (нет данных).
- "Приложения" — сегменты, цвет закреплён за `resource_class` (стабильный
  хэш → цвет из заданной палитры, чтобы одно и то же приложение всегда было
  одного цвета между днями).

Вертикальная красная линия текущего момента — только на сегодняшней дате.

**Низ, по центру, во всю ширину под шкалами** (не справа, как в ManicTime —
левой панели с мини-сессиями не будет вообще): список приложений за
выбранный день — иконка, название, мини-полоска доли дня, длительность.
Сортировка по убыванию длительности. Под списком — строка **Всего: ч:мм**
= сумма всех `active`-интервалов за день.

**Трей**: иконка-индикатор (в духе индикатора ManicTime внизу слева), клик
— показать/скрыть окно, контекстное меню — "Показать/Скрыть", "Выход".

## 6. Настройки (диалог, 3 пункта)

1. Автозагрузка — вкл/выкл (создаёт/удаляет
   `~/.config/autostart/timetrace.desktop`).
2. Тема — Светлая / Тёмная / Синхронизировать с ОС (через
   `org.freedesktop.appearance` XDG Desktop Portal, `color-scheme`; работает
   независимо от тулкита).
3. Порог "не у компьютера" — число минут (по умолчанию 5), применяется
   сразу к активному IdleBackend (пересоздаёт подписку/меняет таймер).

## 7. Упаковка и автозапуск

- PyInstaller собирает автономный бинарник `timetrace` (Python + PySide6 +
  pywayland + python-xlib + файлы GNOME Shell расширения внутри, без
  зависимости от системных пакетов). Бинарник один и тот же для всех DE —
  выбор бэкендов происходит в рантайме, отдельных сборок под KDE/GNOME/XFCE
  не требуется.
- `.deb` и `.rpm` оборачивают тот же бинарник через `fpm`.
- Для Arch — бинарный `PKGBUILD` (устанавливает готовый собранный бинарник
  и `.desktop`-файл, без сборки из исходников на машине пользователя).
- Автозагрузка реализуется файлом автозапуска в `~/.config/autostart/`,
  создаётся/удаляется переключателем в настройках, а не самим пакетом при
  установке (пользователь решает через UI после первого запуска).

## 8. Вне рамок

- Трекинг активного приложения на Wayland-компоситорах вне KDE/GNOME
  (экспериментальные Wayland-сессии Cinnamon/XFCE, Sway, Hyprland и т.п.) —
  для них работает только дорожка "Использование компьютера", если
  применим один из IdleBackend.
- Вкладки "Документы и интернет", "Метки", "Расписание", "Статистика".
- Ручные метки/аннотации сессий.
- Фильтр/поиск по списку приложений.
- Облачная синхронизация — только локальное хранение.
